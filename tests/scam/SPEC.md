# 사기감지 분류기 학습 데이터 작성 지침 (3판, 2026-10-18)

처음에는 Lilju 모델을 대신할 분류기를 직접 학습하려고 만든 지침이다. 분류기 학습은 하지 않고 로컬 LLM 판정으로 바꿨고(2026-10-27), 이 지침으로 쓴 세트(`eval_hard_G/H/I.json`)는 지금 `scripts/measure_scam_llm.py`가 "헷갈리는 문자·통화" 시험 세트로 쓴다(`measure_scam_models.load_sets`).

## 바뀐 이유
- 1·2차 시범은 같은 작성자가 사기/정상 "짝"을 썼다.
- 그러다 보니 정상 글에 요구를 얹어 사기 글을 만드는 모양이 됐다.
- 결과: 인증번호·앱 설치·링크·비밀번호는 사기 쪽에만, 방문·공식 안내는 정상 쪽에만 나왔고, 길이도 한쪽이 길었다(2차 겉모양 AUC 0.85).
- 이렇게 학습하면 모델이 행위가 아니라 단어를 배운다.
- 그래서 **짝을 쓰지 않는다.**

## 무엇을 쓰나
- 한국어 통화 대화 또는 문자·메신저 메시지 한 건을 "대화"라고 부른다.
- 대화마다 맡은 **요소** 하나가 반드시 자연스럽게 들어간다. 다른 요소가 같이 들어가도 된다.
  - 요소 목록은 작성 범위를 고르게 하려는 안내일 뿐 판정 규칙이 아니다.
- 같은 요소의 정상 대화와 사기 대화는 **다른 작성자**가 쓴다. 다른 작성자의 글을 보지 않는다.
- 정상 대화: 그 요소가 실제 정상 생활에서 쓰이는 모습 그대로 쓴다.
  - 예: 은행이 보내는 실제 인증번호 문자, 은행 앱 업데이트 안내, 가족끼리 송금 부탁, 진짜 경찰서 출석 안내, 깜짝 선물이라 비밀로 해 달라는 친구
  - 정상 연락은 사기 예방 문구를 덧붙이지 않는다(실제 은행 문자에 원래 있는 "타인에게 알려주지 마세요" 같은 표준 문구는 괜찮다).
- 사기 대화: 그 요소를 사기범이 쓰는 모습으로 쓴다. 실제 사기처럼 그럴듯하고 정중할 수 있다. 짧을 수도 길 수도 있다.

## 요소
| 번호 | 요소 |
|---|---|
| 1 | 인증번호 |
| 2 | 비밀번호·카드번호·주민번호 등 개인정보 |
| 3 | 앱 설치 |
| 4 | 링크 접속 |
| 5 | 계좌·송금 |
| 6 | 기관 이름(검찰·경찰·은행·공단 등) |
| 7 | 방문·대면 만남 |
| 8 | 급한 기한(오늘까지 등) |
| 9 | 비밀 유지(주변에 말하지 말 것) |
| 10 | 가족·지인의 부탁 |

## 문장마다 사기 표시
- 문장마다 `scam`을 true/false로 표시한다.
- true: **요구·압박·미끼가 정당하지 않은 사람이나 이유로 이루어지는 문장.** 단어가 있다는 것만으로 true가 아니다.
  - 은행 앱이 인증번호를 보내는 문장 = false
  - 전화한 사람이 인증번호를 불러 달라는 문장 = true
  - 실제로는 없는 혜택·위험을 단정하며 행동을 유도하는 문장("지원금 대상자로 선정되셨습니다, 아래에서 신청하세요")도 true다.
- false: 인사, 맞장구, 피해자 말, 자기소개, 근황, 중립적 안내.
- 신뢰를 쌓은 뒤 요구하는 사기(로맨스, 장기 투자 등)는 요구·압박이 처음 나오는 문장부터 true로 하고, 그 앞은 false다.
- 정상 대화의 문장은 전부 false다. 사기 대화에는 true가 최소 1개 있어야 한다.

## 형태
- 통화(call): 두 사람이 번갈아 말하는 받아쓰기체. 화자 표시는 쓰지 않는다. 구어체와 필러를 자연스럽게 섞는다. 6~20문장.
- 메시지(message): 문자·메신저 한 건 또는 짧은 주고받기. 2~10문장.
- 길이는 라벨과 상관없이 범위 안에서 다양하게 쓴다.
- 한 항목에는 한 문장만 넣는다.

## 빼는 경우
- 텍스트만으로 사기와 정상을 구분할 수 없는 대화는 쓰지 않는다. 쓰다가 그렇게 되면 `"ambiguous": true`로 표시하고 남긴다(제외 비율을 라벨별로 확인한다).
- 실존 인물 이름, 실제 전화번호·계좌번호·URL·도메인은 쓰지 않는다.
  - 형식만 쓴다: 010-0000-0000, bit.ly/xxxx, www.xxxx.example
  - 링크 모양은 라벨과 상관없이 섞어 쓴다.
